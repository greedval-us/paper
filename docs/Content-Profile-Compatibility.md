# Профиль и совместимость контента

Текущая версия профиля — **7**. Запись страницы хранит стабильный ID основания, список `WeaponMounts` с индексами `0..2`, ID оружия и формой каждого крепления, а для каждого модуля — отдельные `InstanceId` и `DefinitionId`. Слот 0 обязателен; пустой слот 1 не сдвигает слот 2. Старые числовые значения `StructureKind`, `ChassisKind` и битов `TowerModules` не меняются; поля этих типов нужны адаптерам исторических профилей.

## Чтение и миграция

| Версия | Чтение |
|---|---|
| 1 | Историческое восстановление стартовых страниц и четырёх слотов; рисунки ещё не сохранялись. |
| 2 | Строгая проверка профиля; рисунок формата 1, семь исторических привязок. |
| 3 | Строгая проверка; рисунки форматов 1–2, включая восьмую привязку Rail. |
| 4 | То же, плюс сохранённая форма миномёта с исторической границей отношения сторон 3. |
| 5 | Стабильные ID и экземпляры модулей; рисунки форматов 1–3; сохранённая оценка и её версия. |
| 6 | Индексированные `WeaponMounts`, до трёх креплений с независимыми формами; сохранённая оценка с ресурсными и архивными пояснениями. |
| 7 | Свободные функциональные рисунки: `Origin = Freeform`, `FreeformRuleVersion = 1`; прежние страницы сохраняются без потери линий. |

Миграция записывает версию 7 только при успешном сохранении. Перед заменой исторического файла v1–v6 `WorkshopProfileStore` создаёт точную копию фактически прочитанного исходника `<profile>.vN-original`. Чтение само не переписывает файл. Алгоритм временного файла, проверки прочитанных байтов и резервной копии `.bak` сохранён. Формы v4/v5 переносятся из первого и второго креплений; v1–v3 получают круги.

Свободные конструкции v7 хранят `Origin = Freeform` и `FreeformRuleVersion = 1`. Геометрия определяет характеристики; исторические оценки больше не дают штрафа за точность. Неизвестная версия правил защищает файл от перезаписи. Подробнее — [правила геометрии](Freeform-Towers.md).

Открытия заготовок используют устойчивые ID в существующем массиве `Unlocked`; новая версия DTO не нужна. Стартовые права также записываются при подготовке каталога и не отзываются, если позже поменялся `InitiallyUnlocked`. Покупка проходит через сохранение кандидата: при отказе записи золото и открытия исходного профиля остаются прежними.

Проверка формата при чтении не применяет текущие пороги размеров и лимит чернил: баланс может измениться или отличаться у каталога. Старый рисунок сохраняется для исправления. Проверки полноты, лимита и итоговых характеристик выполняются при применении текущей конфигурации, сохранении, испытании и строительстве.

## Удалённые и отключённые определения

В профилях v5–v7 отсутствующий в текущем каталоге ID не считается повреждением файла. Он сохраняется в открытиях, страницах, слотах и экземплярах модулей вместе с авторскими линиями и зафиксированной оценкой. Отключённое определение обрабатывается так же: открытие и рисунок остаются. Запуск партии или сохранение изменённой сборки требуют доступных определений, совместимости модулей, допустимых слотов и достаточной грузоподъёмности; эти проверки выполняются при подготовке, без очистки старых данных.

Новый каталог может добавить стартовые открытия при подготовке мастерской. Он не отзывает прежние открытия. Рабочая копия профиля сохраняет текущие страницы и слоты без повторного добавления удалённых пользователем стартовых страниц.

Для нового профиля начальные открытия, страницы и назначение четырёх слотов берутся из каталога (`StartingPages`), включая пустой список и неназначенные слоты. Исторические C#-стартеры используются только адаптерами и явными legacy fixtures. Существующий профиль не получает стартовые страницы заново.

## Рисунки и архивная оценка

Формат рисунка 2 / схема привязок 1 сохраняется для восьми исторических привязок и удерживает совместимые хеши. Новые привязки, включая `mount.2` и `module.<InstanceId>`, записываются форматом 3 / схемой 2. Каждое крепление сохраняет собственные линии. Сохранённая оценка содержит версию правил, сигнатуру эталонов, хеши рисунка и состава и обратную связь по привязкам. Если эталоны или настройки оценки изменились, прежняя оценка остаётся архивной; изменение геометрии или состава требует новой оценки. Известные старые пояснения преобразуются в ресурсные сообщения, неизвестные получают нейтральную архивную подпись с исходным текстом в `ArchivedMessage`. Положительная версия самих правил не является номером схемы DTO.

## Защита от перезаписи

Более новая версия корневого профиля, DTO страницы, рисунка или схемы привязок переводит хранилище в защищённое состояние. Неизвестные исторические числовые детали или права также защищаются, поскольку адаптер не может достоверно преобразовать их в ID. Защита остаётся активной на повторных чтениях и проверяется ещё раз перед записью; совместимая `.bak` не разрешает заменить более новый основной файл. Ошибки записи не публикуют незафиксированный ручной кандидат поверх текущего профиля.

Проверки используют отдельные временные каталоги. Реальный профиль игрока не нужен для миграционных тестов и сценариев приёмки A–E.

Подготовка `RunController` требует назначенного `balanceAsset` и проверяет конфигурацию до чтения профиля. Исторические фабрики без ассета доступны только через явный параметр `allowLegacyFixtureDefaults: true` для изолированных проверок; он выключен по умолчанию и запрещён вместе с автоматическим выбором реального пути профиля.
