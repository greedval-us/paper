## Этапы

| Этап | Экраны | Работа | Критерий готовности |
|---|---|---|---|
| 1. Общий визуальный набор | Все | Бумага, клетка, линии, заголовки, кнопки, вкладки, карточки, выбранное/закрытое/недоступное состояние, модальные окна | Отдельные UI-элементы читаемы; оформление сопоставлено с растровым альбомом, данные не запечены в PNG |
| 2. Вход и подготовка | 01–03 | Меню, карта текущей миссии, четыре страницы и материал | Весь путь до старта работает с настоящим набором; отмена выбора сохраняет прежние данные |
| 3. Мастерская и альбом | 04–09, 24 | Четыре шага, выбор деталей, большой холст, сводка, подробности, имя и страницы | Рисунок редактируется, варианты сохраняются, четыре слота уникальны, возврат не начинает бой |
| 4. Пробы и особые редакторы | 10–14 | Полигон, заготовки, отпечаток мортиры, веер, броня | Окна связаны с выбранным слоем/креплением и общими игровыми расчётами, правки не теряются |
| 5. Поле и боевой HUD | 15–17 | Компактные панели, чертежи/постройки/инструменты, ресурсы, прогноз, контекст объекта | Поле остаётся читаемым; полный набор инструментов работает, клики по UI не строят на поле |
| 6. Завершение и служебные экраны | 18–23 | Пауза, усиления, результаты, настройки и помощь | Пауза и окна блокируют ввод; итоги и статус записи соответствуют реальному результату |
| 7. Ошибки и подтверждения | 25–28 и состояния всех экранов | Покупки, недостаток ресурсов, отказ записи, проблемный слой, выход | Ошибка названа, черновик доступен, отмена безопасна, успех не показывается до выполнения команды |
| 8. Совместная проверка | Все 28 | Сравнение с эскизами, размеры окна, текст, фокус, сохранения, игровой маршрут | Есть снимки Unity и результаты соответствующих тестов; оставшиеся различия записаны явно |

Каждый этап переносит оформление поверх действующих команд. Изменение баланса, форматов профиля или правил рисунка не входит в визуальный перенос. Ошибочные или неполные числовые примеры PNG исправляются по игровым данным.

## Рабочий порядок для каждого экрана

1. Сопоставить PNG, его цель в [каталоге экранов](Game-Design.md) и существующие игровые команды.
2. Собрать элементы в основной сцене/её UI; текст, значения и действия подключить к текущим данным.
3. Проверить обычный, выбранный, недоступный и ошибочный варианты, которые применимы к экрану.
4. Сравнить снимок Unity с эскизом, проверить размеры окна, фокус и пересечения ввода.
5. Запустить проверки затронутого поведения и отметить результат в новом отчёте.

Для нового интерфейса не возвращаются удалённые стенды и техническая сцена. Используются основная игровая сцена, автоматические проверки и профиль в памяти/изолированные сохранения по [руководству разработчика](Development-Guide.md).

## Что пока не подтверждено

Нет перенесённых по этим эскизам экранов, снимков их реализации в Unity и результатов визуальной приёмки. Прежние успешные тесты относятся к технической основе. Завершение этапа нельзя отмечать только по наличию одноимённого класса, PNG или работающей HTML-страницы.
