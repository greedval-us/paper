# Контракты механик

Механики рабочего пресета настраивает разработчик в `BalancePresetAsset.rules.Mechanics` перед созданием партии. `GameBalanceAsset.dataPreset` выбирает пресет; поле `GameBalanceAsset.mechanics` относится к явному legacy-адаптеру и при назначенном пресете не применяется. Игроку выбор систем не предоставляется. Полный состав систем — в [реестре действующих механик](Current-Mechanics.md).

`MechanicsConfiguration` содержит разрешения, `MechanicsAvailability` фиксирует их с учётом прежних master gates. Партия, оружие и read model используют захваченные возможности. Изменение asset влияет на следующую партию. Горячая замена систем не поддерживается. Остальные поля `GameBalance` по прежнему контракту нельзя менять во время партии.

## Границы и отключения

| Механика | Владелец | Контракт отключения |
|---|---|---|
| Прорисовка врагов | Спавн, `EffectsRules` | `EnemyDrawingTiers=false`: Sketch, без защиты прорисовки и множителя HP. Исторический рост HP применяется только при старом master=false |
| Кляксы | `CorpseBlotSystem`, `IBlotContext` | `CorpseBlots=false`: нет создания, поглощения, бафа и очистки. Ручная команда отказывает без расхода; автоматическое орудие простаивает |
| Дальние атаки | Спавн, очередь `EnemyGlob` | `RangedEnemies=false`: доля плевунов переходит обычным каракулям; остальные типы и уровни рисунка сохраняются |
| Чернильницы | Цели, маршруты, добыча | `InkWells=false`: нет точек, резервных клеток, дополнительных целей или цветной добычи. Основная база и обычные награды сохраняются |
| Цветные картриджи | Команды, `ColorEffectPayload` | `ColorCartridges=false`: цветные команды отклоняются атомарно; оружие передаёт пустой payload. Обычный урон и замедление скрепкострела сохраняются |
| Улучшения партии | `GameSession.Progression` | `RunUpgrades=false`: выбор не появляется и не блокирует следующую волну. Награды волн и золото продолжают начисляться |
| Свободное рисование | `FreeformGeometry`, `FreeformTowerDesign`, `TowerCatalog`, оружие, preview, полигон | Исторический флаг `DrawingQuality` не влияет на темп. Рисунки нового происхождения Freeform используют версию правил1; геометрия обязательна для готовой конструкции. |
| Подача креплений | `TowerConstructionRules`, `WeaponSystem` | `Construction.DynamicFeed=false` использует историческую фиксированную подачу; текущий Target делит подачу основания между 1–3 действующими креплениями |
| Запись профиля | `IWorkshopProfileStore`, Application | Существующий memory-only режим оставляет мастерскую и игру работоспособными без IO |

Старый `EnableEnemyMechanics` ограничивает первые три системы одновременно; старый `EnableInkWells` ограничивает чернильницы. Для независимых отключений оставляйте master gates включёнными и меняйте отдельные разрешения. Target-пресет сохраняет developer configuration.

Чернильницы являются источником цветных чернил, но не владельцем цветных статусов. Полигон может задавать цвет без экономики партии. Явный контекст клякс полигона не требует исторического спавна клякс; новый `CorpseBlots=false` отключает и такой контекст.

Все 128 сочетаний проверяются коротким боем с реальным строительством и завершением трёх волн. Это проверяет независимость систем и жизненный цикл. Проходимость полной кампании с другим набором механик требует отдельного балансирования.

## Слои

| Слой | Ответственность | Ограничение |
|---|---|---|
| Core | Правила, состояние, команды, события, read model | Не зависит от Unity, UI, IO или Application |
| Application | Адаптация asset, запуск, команды, профиль | Владеет IO и жизненным циклом |
| Presentation | Отображение read model, команды Application | Не списывает ресурсы и не рассчитывает правила боя |
| Editor / Tools | Экспорт конечных настроек и Excel | Не является runtime-зависимостью |

`GameSession` координирует фиксированный шаг. Статусы продвигаются независимо от источника, затем обновляются кляксы и дальние снаряды. Общие выплаты и улучшения находятся в `GameSession.Progression`, добыча цвета — в системе целей. Оружие получает узкий `IBlotContext`, а не всю сессию.

Пока `PendingUpgrade=true`, отсчёт подготовки между волнами сохраняется. После выбора улучшения отсчёт продолжается с сохранённого значения; игрок также может явно запустить волну. Строительство и перезарядка продолжаются по обычным правилам, остановка всей симуляции остаётся отдельной паузой.

## Расширение

1. Определите владельца состояния, входы, результаты и нейтральное поведение.
2. Для необязательной системы добавьте разрешение в config и availability; протяните через adapter, snapshot, полигон и read model.
3. Проверяйте доступность до оплаты и изменения состояния. UI отражает результат, но не заменяет проверку Core.
4. Добавьте тест отключения и тест соседней системы, которая должна продолжить работать. Расширьте проверку сочетаний.
5. Обновите описание механики и Excel. Полный словарь public-полей экспортируется автоматически.

Отключение поведения не удаляет определения, enum ID, открытия или сохранённые страницы. Физическое удаление сохранённого типа требует миграции формата.

## Excel

Книга `docs/balance/PaperDefense-Mechanics-Balance.xlsx` строится из `CreateWorkshopBalance()` обоих asset. Рабочие пресеты уже содержат конечные правила; повторное преобразование Target и генерация legacy-угроз не выполняются. Обновление: [руководство генератора](../Tools/BalanceWorkbook/README.md). Формулы сверяются с `TowerCatalog`; редактирование книги автоматически не меняет игру.
