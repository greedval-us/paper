# Источники параметров

В каталоге `album-v1.4` 91 определение, включая 36 частей сооружений. Параметры импортируются в PlayerAssemblyCatalog, где их проверяют теми же правилами, что используются в игре. [Формулы](Component-Stats-and-Abilities.md) и [методика сверки](balance/README.md).

## Основная игра сейчас

Источник: [PlayerBalance.asset](../Assets/PaperDefense/Configuration/Game/PlayerBalance.asset) → [PlayerRules.asset](../Assets/PaperDefense/Configuration/Game/PlayerRules.asset) → [PlayerContent.asset](../Assets/PaperDefense/Configuration/Game/PlayerContent.asset) → [PlayerAssemblyCatalog.asset](../Assets/PaperDefense/Configuration/Game/PlayerAssemblyCatalog.asset). Фактический снимок основной игры: [assembly-runtime.json](balance/assembly-runtime.json), экспортированный `BalanceWorkbookExport.ExportPlayerAssembly()`.

| Параметр | Действующее значение |
|---|---|
| Профиль | Writer v9; совместимое чтение v1–v8 |
| Слоты | 8 общих слотов башен и сооружений |
| Стартовый ресурс | 340/364/388 · 600/680/880 · 980/1040/1160 штрихов по страницам трёх тетрадей |
| Строительство между волнами | Гарантированная выплата за завершение волны учитывает размер следующей орды и активные входы. На странице 1-1 выплаты составляют 242, 282 и 322 штриха |
| Завершённая волна | 7/8/9 золота + 10/12/14 XP по тетради |
| Победа | Награда страницы, отдельный first-clear и открытия |
| Кампания | 9 страниц, 59 волн, короткие страницы и длинные финалы |
| Уровень игрока | 1–8 |
| Обоймы | Состояние заряда, цикл выстрелов и перезарядка |

Кампания рассчитывает выплату по фактическим входам следующей волны. На стройку выделяется 210 штрихов, по 8 за каждый дополнительный и каждый вновь открытый вход, ещё по 8 за каждые полные 120 врагов сверх 300. Действуют нижняя граница выплаты самой страницы и резерв в 40 штрихов на полевую модернизацию начиная с 2-2. Финальная волна завершает миссию, поэтому надбавка на следующую оборону к ней не применяется. [Расчёт выплат кампании](../Assets/PaperDefense/Core/CampaignHordes.cs).

На странице 1-1 за 325 из стартовых 340 штрихов можно построить два дозора (по 40), пробивную башню (60), мортиру (99), четыре секции стены (по 16) и замедляющую плитку (22). По одной постройке с каждой из восьми начальных страниц альбома стоят вместе 426 штрихов. При продолжении сохранённой миссии игрок сохраняет остаток штрихов на момент передышки.

Сумма цен на 91 деталь составляет 3793 золота. Некоторые из них игрок получает за первые победы. Чертежи трёх дополнительных семейств стоят ещё 245 золота в сумме. Стартовые башни сохраняют базовую цену и DPS; варианты деталей меняют конкретные характеристики. Урон по площади и пробитие нельзя оценивать одним множителем DPS без сценария расположения целей.

## Границы источников

`Historical.asset` и `Target.asset` — отдельные пресеты для технических сравнений. Экспортёр `Tools/BalanceWorkbook` работает с ними; его таблица не заменяет основной баланс. Действующий составной каталог строит `Tools/AlbumDesign2026/build-data.mjs`; независимая проверка сравнивает расчёт с экспортом основной игры.

`BalanceValidation.Validate` проверяет конфигурацию до старта. `GameSession`, `WeaponSystem` и `TrialRunner` используют снимки; изменение исходного asset не должно менять уже начатый бой. Порядок слияния записей описан в [архитектуре контента](Content-Architecture.md).

Числовой авторский источник — build-data.mjs и его [album-balance-v1.json](balance/album-balance-v1.json). При изменении данных выполните импорт, свежий runtime-экспорт и независимую сверку по [инструкции](../Tools/AlbumDesign2026/README.md). Дата и формулировка статуса в метаданных версии JSON не заменяют фактическую проверку импортированных assets. Изменения Excel не импортируются в JSON или игру автоматически.

Каталог `album-v1.2` добавил шиповую ловушку и маяк наводки к составу v1.1. Штатный генератор: 60/18 штрихов, быстрый: 50/14, окупаемость обоих — 4 полностью пережитые волны. Экономичное оснащение даёт 27/21 и снижает прочность до ×0,85. Старые сохранённые снимки v1.0 сохраняют исходные числа; [контракт сохранения](Component-Stats-and-Abilities.md#альтернативы-v11-и-сохранённые-числа). Политики бюджетов, волн, наград и проверки проходимости описаны в [кампании](Campaign.md).
