## Ошибки реализации

1. **Ложное подтверждение сохранения.** `Application/RunController.cs:116–130` игнорирует bool `WorkshopPersistence.Save`. Альбом/покупка/слот меняются в памяти, команды возвращают успех, HUD пишет «сохранён»/«открыта навсегда» даже после отказа диска. Проверка: `Presentation/UI/WorkshopHud.cs:130,182`.
2. **Резервная копия не восстанавливается и может быть затёрта.** `Application/WorkshopPersistence.cs:13–26` читает только primary, иначе возвращает стартовый профиль. Затем `RunController.cs:117` пишет при выходе, а `WorkshopPersistence.cs:35` заменяет `.bak` прежним, возможно повреждённым primary. Добавить чтение `.bak` без защиты следующей записи недостаточно.
3. **Полигон игнорирует настройки партии.** `RunController.cs:167–171` не передаёт баланс, `Core/TrialRunner.cs:23` создаёт стандартный. Preview использует `session.Balance` (`RunController.cs:148–149`). Текущий asset совпадает со стандартными числами оружия: штатное численное расхождение сейчас скрыто, ошибка проявляется при настройке.
4. **Одно направление двух стволов.** `Core/WeaponSystem.cs:77` записывает общий Aim; `DoodleGlyphs.cs:91–92` использует его для обоих креплений. Реальные цели уже выбираются отдельно; визуальное направление второго оружия может соответствовать последнему выстрелившему, а не его собственной цели. Общий захват на `WeaponSystem.cs:39–51` также требует явного решения для независимых креплений.

## Упрощения и новые предложения

- Фиксированная подача, материал ×урон и броня ×HP — текущие намеренные правила; их замена требует отдельной оценки баланса.
- Бесконечное ожидание ради штрихов на `PendingUpgrade` подтверждается `GameSession.cs:239–242,268`. Это экономическая лазейка, но отключать весь доход в первом этапе нельзя: `Salvage` повышает `supplyMultiplier` на 25% (`:209–212`).
- Горение сейчас обходит защиту (`EnemyEffects.Advance`); зелёный эффект влияет уже на нанесшее его попадание (`EnemyEffects.ApplyHit`). Не менять молча при стандартизации.
- Лимит чтения — 1 Mi символов, запись размер не проверяет. Для нынешних 64 коротких страниц обычными командами лимит не достигается; после добавления штрихов необходим общий лимит UTF-8 и проверка до замены файла.
- `WorkshopProfile.FromData` сохраняет 64 валидные пользовательские страницы и чинит набор без вытеснения, но молча пропускает невалидные записи. Для пользовательских рисунков потребуется диагностика и сохранение исходного файла.
- Ручное рисование, оценка, конечная экономика и новые детали — новые подсистемы/этапы. Процедурный рисунок не считается авторским.
