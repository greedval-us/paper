# Задача 5 — команды сборок и транзакции

База: `7e33192`. Unity `6000.5.7f1`. Все файловые проверки используют изолированные временные профили.

## Реализация

- `AssemblyCommands` работает через владельца текущего профиля — `RunController`. Покупка, сохранение страницы/библиотечного компонента, создание варианта, удаление, перенос назначения и явное применение библиотечной ревизии строят candidate и вызывают существующий `SaveCandidate`. Только успешная запись публикует новый профиль и событие `WorkshopChanged`.
- Receipt операции хранится в том же candidate. Повтор после успешного commit, в том числе после перезапуска, возвращает исходный `ResultId`; другая разновидность команды с тем же GUID отклоняется. Вариант получает ID из GUID операции в формате N, поэтому отказ записи не меняет будущий ID варианта. GUID сравниваются по значению, включая uppercase-N receipts старого writer.
- `MetaProgression.LevelForXp` реализует восемь порогов `0/100/230/390/580/800/1050/1330`. Покупка требует уровень и золото; уже купленное право не оплачивается повторно и не блокируется уровнем. Покупка не устанавливает деталь в сохранённые страницы.
- Входящий snapshot редактора считается черновиком. Writer сборки заново собирает определения по ID/revision из авторитетного каталога, проверяет права, численную допустимость для всех разрешённых материалов и геометрическую пригодность. Поддельные числовые определения не публикуются. Архивные страницы при назначении и запуске используют собственный snapshot, без поиска той же ревизии в текущем каталоге.
- Правка создаёт следующую ревизию; устаревшая ревизия отклоняется. «Как вариант» создаёт отдельную страницу, соблюдая предел 64. Изменение библиотечного компонента не меняет готовую страницу; `ApplyLibraryEntry` делает это явно новой транзакцией. Удаление библиотеки сохраняет собственный snapshot страницы. Удаление страницы очищает её слоты, перенос ID освобождает прежний слот — оба изменения публикуются только после записи.
- `StartRun` фиксирует `RunLoadoutSnapshot`: восемь уникальных ссылок, собственные страницы и баланс, численные результаты и разрешение других материалов по замороженным правилам. Пустые позиции допустимы, хотя бы одно оружие должно наносить врагам урон. Промокашка и поддержка не считаются атакой. Изменение исходного списка, каталога, страницы или выдаваемой наружу копии баланса не меняет начатый набор.

## Границы этапа

Новые публикации проходят строгий fit gate задачи 3. Отсутствующее физическое покрытие возвращает диагностику; оно не подменяется одной численной проверкой. Полное покрытие семейств относится к задаче 13. Уже принадлежащие игроку стартовые и архивные страницы остаются доступны в наборе по своим численным снимкам. Новый цикл оружия и строительство по resolved-слотам подключаются задачами 6–7; старый tower-only адаптер пока сохранён для существующего интерфейса.

Подготовка переходов отделена от публикации. Ошибка новой конфигурации сохраняет прежние session, profile и frozen loadout. Исключение UI-подписчика после успешной публикации не превращается в ложный отказ транзакции или запуска: оно распространяется отдельно, а durable receipt предотвращает повторное списание.
