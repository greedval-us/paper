## Действительные данные и ограничения

- Карточки и победная группа используют реальные snapshots; кнопки сохраняют callbacks, права покупки, выбор и удаление.
- Итоговые золото/XP, receipt, pending-save и retry-save берутся из действительного run/profile состояния.
- Полоса XP заполняется как `(TotalXp − LevelStartXp) / (NextLevelXp − LevelStartXp)`. Подпись показывает накопленный XP и следующий настоящий порог. На последнем уровне полоса полная; новый порог не выдумывается.
- Геометрия основы соответствует фактическому рецепту. Широкая двухместная основа может отличаться от компактной круглой основы в эскизе; иллюстрация не подменяется готовой картинкой другой сборки.
- Дополнительные действующие возможности (восстановление стартового набора, удаление, фильтр Standard, дополнительные настройки) сохранены. Число контролов поэтому может отличаться от концепта.
- После этого изменения требуются свежие PNG и ручное сравнение. Наличие или корректная metadata не являются визуальным PASS.

## Галерея

Запуск: `node Tools/ArtAssembly13/build-fidelity-gallery.mjs`. Строгая полнота: тот же вызов с `--require-complete`.

Генератор пишет только новые `scene-fidelity-gallery.html` и `scene-fidelity-gallery-data.json`. Источники и старые Task13 gallery/report не перезаписываются. Canonical30×5 берутся из `task13-visual-states.json`; пути после меняют префикс `task13-` на `fidelity-` и используют папку `fidelity-screenshots`.

Для каждого PNG проверяются сигнатура, IHDR/структурная полнота, размеры; рядом проверяется JSON с теми же размерами, canonical name, artRevisionv6, одним Canvas, frame и изолированной сценой. Старые Task13 кадры проверяются против историческойv5. SHA-256 сохраняется в data JSON. До получения новых кадров отображается MISSING; устаревшая или неполная provenance — INVALID. READY подтверждает только эти проверки. В галерее есть три колонки, переключение крупного A/B и матрица всех150 кадров; автоматического визуального PASS нет.
