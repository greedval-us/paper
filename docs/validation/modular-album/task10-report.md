# Задача 10 — альбом, меню, карта и восемь слотов подготовки

Дата: **19.10.2026**. База: `e92a5d25d28e236eb8282d96a44a05a5acf9bd7a`. Unity **6000.5.7f1**, существующая ветка `codex/standard-workshop-stage1`.

Функциональный перенос задачи 10 проверен. **Полное художественное совпадение с эскизами пока не достигнуто**: оставшиеся различия перечислены ниже и входят в графическую приёмку задачи 13. Задача 11 не начата.

## Реализация

- Настроенный составной маршрут открывает отдельный `AlbumPanel`: Все / Башни / Сооружения / Стандартные / Мои, выбор страницы по постоянному ID, редактирование, сохранение варианта, подтверждение удаления и назначения. Пустой фильтр «Мои» сохраняет доступ к стандартным страницам. Прежний `WizardAlbumPanel` оставлен для явно выбранного маршрута совместимости; значение `PlayerPage.Album` добавлено в конец enum.
- Подготовка показывает **8 слотов** в сетке 4×2 на всех трёх проверенных размерах. Все индексы 0–7 назначаемы; очистка оставляет пустое место, повтор страницы требует подтверждения переноса. Цена и параметры берутся из общего resolver. Генератор показывает цену и ограничение «Только карандаш». Имя до 48 символов не закрывает действия. Меню, карта и основной набор подготовки не требуют прокрутки; каталог альбома прокручивается внутри своей области.
- `CanStartAlbumRun` и запуск используют общую подготовку набора. Проверка готовности не пишет профиль и не публикует боевой snapshot; состав только из поддержки не позволяет начать бой.
- Главное меню и карта получили вход в альбом. Карта показывает фактическое число назначенных страниц; после закрытия альбома возвращает на карту. Меню, карта и подготовка показывают настоящий уровень/XP. Возврат из мастерской учитывает исходную страницу; после сохранения альбом восстанавливает выбранный ID и подходящий фильтр. Отмена не создаёт страницу.
- Восстановление стартового набора добавляет только отсутствующие стартовые ID. Уже существующие страницы, включая изменённые страницы с таким ID, не перезаписываются. До публикации проверяется место сразу для всего набора; сообщение показывает, сколько страниц нужно освободить. Золото, XP и слоты сохраняются. Команда использует обычную запись кандидата и receipt, отказ IO ничего не публикует, повтор операции не создаёт дубли.
- Исправлено чтение необязательного `OperationReceiptData.ResultId`: `JsonUtility` превращает null в пустую строку, из-за чего транзакции очистки/восстановления не проходили повторную проверку сохранения v8. Null и пустая строка теперь означают отсутствие ID; непустой ID по-прежнему валидируется. Версия схемы не менялась.
- Добавлены **57** ключей русского текста с контрактами аргументов. Существующие тексты сохранены. Строгая проверка новых пользовательских сборок и права на детали не ослаблялись; восстановление доверенных стартовых рецептов остаётся отдельной операцией.

Проверка восьми слотов дополнительно подтверждена контролируемым отключением только входа в новую подготовку: обязательный тест увидел отсутствие всех восьми новых карточек и завершился RED. Эскизы остаются целевым образцом для композиции, рисунков и стиля. Текст и числа — живой UI; при смене пропорций экрана раскладка адаптируется. Текущая проверка подтверждает работоспособность и доступность, **но не закрывает художественную приёмку**:

- Альбому ещё нужны декоративное окружение из эскиза 09, крупные полноценные рисунки всех семейств, оформление восьми назначений и окончательная типографика. При 1280×720 длинные названия в верхней полосе переносятся теснее, чем в эскизе.
- Пустому состоянию нужна композиция большого открытого блокнота из эскиза 24. Нынешняя пиктограмма — временное отображение.
- У подготовки и карточек сохраняются схемы семейств для неподтверждённых рецептов; генератор пока обозначен карандашом. Полное покрытие 54 деталей и четыре семейства сооружений относится к задаче 13.
- Карта сохраняет адаптивную колонку и отличается оформлением показателей; меню использует добавленную живую панель профиля.

Задача 13 должна проверить все 30 экранов на трёх размерах с pass/fail и остаточными дефектами, а также layout на 1280×960 и 1600×900. Побитное совпадение изображения при разных пропорциях экрана и готовый Player build здесь не заявляются.
