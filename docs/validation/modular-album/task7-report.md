# Задача 7 — общая постройка, баррикада, замедление и ремонт

База: `0a58ea1`. Unity `6000.5.7f1`.

## Реализация

- `GameSession.QuoteEntry/TryBuildEntry` используют существующую проверку размещения для башен и сооружений. Современные стены выбирают участки баррикад, замедлители — проходимые клетки дороги, остальные объекты — землю для построек. На открытой карте действуют прежние ограничения границы, замка, колодцев, врагов и ландшафта. Занятая клетка отклоняет весь новый пакет; повторные координаты оплачиваются один раз. Все экземпляры готовятся до оплаты и публикации в сетке.
- По одному экземпляру восьми стартовых страниц стоят **426 штрихов**, остаток из **640 — 214**. У экземпляра свои ID, оплаченная стоимость, материал, HP, время постройки и неизменяемый `ResolvedEntry`. Повторная установка тратит боевой ресурс, без новой покупки деталей или записи профиля. Материал в Core должен совпадать с материалом переданного расчёта; Application получает нужный расчёт из замороженного набора.
- Постройки используют общую занятость, завершение/ожидание освобождения клетки, навигацию, попадания, разрушение, продажу и статистику. Баррикада имеет конечную стоимость прорыва; замедлитель занимает клетку строительства и остаётся проходимым. Уничтожение освобождает клетку и записывает реальный расход. Возврат учитывает оплаченную цену, долю HP и политику материала. Генератор получает отдельный тип без перенумерации исторических значений; его ограничения установки — максимум 2, только карандаш, возврат 0. Доход за волны остаётся задачей 8.
- Смена материала пересчитывает собственный рецепт по замороженным правилам, оплачивает разницу, сохраняет долю HP и прогресс обойм. Прежний `StructureView` продолжает держать прежний снимок. Усиление HP партии применяется один раз; скорость ремонта от материала, цвета и усилений не растёт. Цвет сохраняет существующую систему оружейных картриджей: цену по карандашной странице, проверку запаса и запрет окраски поддерживающих сооружений.
- `StructureSupportRules` рассчитывает эффекты без изменения входного состояния. Каждый новый ремонтный пост выбирает одну ближайшую повреждённую живую завершённую постройку, при равенстве — меньший ID; себя и другие посты не лечит. Несколько постов на цели дают максимум скорости, включая сочетание со старыми постами. Старые посты сохраняют прежний охват всех целей. Общая публикация ремонта ограничивает HP максимумом и обновляет навигацию при переходе полосы здоровья.
- Замедлитель применяет радиус 1, скорость `.6` и собственную длительность после выхода. Действует сильнейшее замедление, без перемножения и ниже `.4` не опускается. Незавершённая или погибшая поддержка не действует.
- `DamageRules` использует рассчитанную общую защиту с пределом `.6`. Фронтальный щит `.4` действует в замкнутом секторе `90°` относительно `StructureState.Aim` основы; направление каждого ствола независимо. Общая и фронтальная защита объединяются максимумом. Новая постройка и полигон начинают с одинакового направления основы; стрельба не поворачивает щит. Историческая геометрия распределённой брони сохранена.
- Команды `RunController.QuoteEntry/BuildEntry` получают страницу и материал только из `RunLoadout`. Старые команды башен направлены через тот же адаптер. При начале партии фиксируется запрет инструментов вне слотов: он действует для настроенного нового режима даже с полностью историческим альбомом и не снимается изменением каталога после старта. Старые явные fixture-команды без нового каталога сохранены для совместимости. Жест по современной стене/замедлителю строит линию; башни, ремонт и генератор устанавливаются по одному.
- Минимальный адаптер `NotebookWorldView` читает время постройки и дальности из `ResolvedEntry`. Все восемь типов можно привязать к действующему рендеру, включая генератор без исторического определения в балансе. Полное новое изображение объектов остаётся дальнейшим этапом.

## Границы этапа

Генератор уже размещается и разрушается по общим правилам; доход и надёжные награды профиля выполняются задачей 8. Боевой HUD, полный перенос ввода и экранов, сценарии полигона для поддержки и художественное покрытие выполняются следующими задачами плана. Реальные профили не читались и не изменялись; проверки приложения используют временные пути. Player build на этом этапе не заявляется.
