Счётчики GC разных поколений на Mono могут описывать одни и те же сборки и **не суммируются**. Резервный `GetAllocatedBytesForCurrentThread` не прошёл реальную калибровку в Player и отмечен недоступным. Отсутствующие метрики не считаются нулевыми. `performanceComplete:false` сохранён. Пользователь выбрал скрытое окно и принял ограничение GPU; видимое окно не открывалось. Наблюдаемой CPU-регрессии в этом smoke нет; обещания прироста производительности или полной GPU-приёмки нет.

После двух прогревочных циклов сняты пять контрольных состояний меню → мастерская → полигон → бой. В памяти: **266 GameObjects / 910 Components**, временный store: **266 / 911**, без роста во всех пяти состояниях. Четыре наблюдаемых события (`WorkshopChanged`, `SessionChanged`, `SimulationEventReceived`, `SelectionChanged`) постоянно имеют **1 / 2 / 1 / 0** подписчиков. Проверяются эти события, не все возможные подписки приложения. Managed heap колеблется при сборках мусора.

## Воспроизведение

Полные Unity-тесты запускаются отдельно в EditMode и PlayMode. Для нативного XML включить `AlbumReleaseTestResults.Enable("EditMode")` / `Enable("PlayMode")`, после прогонов вызвать `Disable()`. Собрать через `PlayerGameSceneTools.Build()`.

`Tools/Release/run-player-checks.ps1` принимает `-BuildDirectory`, `-OutputDirectory`, `-ProfilePath`. Store должен быть новым, отдельно подготовленным внутри системного Temp, с законными Gold/XP для первой закрытой детали (здесь 94/120). Использованный store уже содержит покупку; для повторения всего сценария нужен новый fixture. Скрипт последовательно выполняет четыре скрытых запуска, требует код 0 и успешные JSON. Перезапуск сравнивается с полным отчётом предыдущего процесса.
