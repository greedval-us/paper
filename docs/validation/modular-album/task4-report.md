# Задача 4 — профиль v8 и миграция

База: `6cbeea5`. Unity `6000.5.7f1`. Миграция и проверки выполнялись на временных файлах; личный профиль не использовался.

## Реализация

- Профиль v8 хранит XP, собственные снимки страниц, библиотеку основ/оружия, квитанции наград и операций, восемь ссылок набора. Квитанции используют GUID в строковом формате N. Сохранённая страница содержит все нужные определения деталей и не зависит от существования библиотечной записи или той же ревизии в текущем каталоге.
- Reader v1–v7 использует фиксированные четыре исторических слота. Он переносит первые четыре ссылки, золото, страницы и права; добавляет четыре пустых слота и XP=0. Альбом из 64 страниц не вытесняется стартовыми объектами. Бесплатное сооружение можно импортировать после освобождения места.
- Стандартная башня преобразуется только при явном историческом балансе и совпадении параметров для всех материалов, каждого оружия и каждого числа активных установок. Проверяются также интервалы стрельбы и перезарядки: совпадение суммарного DPS само по себе недостаточно. Неподтверждённая или пользовательская страница остаётся Legacy с исходными данными. Неизвестные стабильные legacy ID сохраняются без подстановки стандартных деталей.
- Новая установка через настроенный `RunController` получает восемь страниц каталога и восемь выбранных ID, включая четыре сооружения. Старый tower-only API остаётся временным адаптером; он не может перезаписать составную страницу и уничтожить её snapshot.
- Загрузка строит отдельный candidate. Проверка будущих схем проходит по всему профилю до структурной проверки: повреждённая ранняя запись не скрывает более новую схему в конце файла и не разрешает откат на writable backup. Неизвестная вложенная версия или отсутствующая embedded ревизия защищает исходный файл от записи.
- Writer проверяет сериализацию и прочитанный временный файл, сохраняет точные байты исторического оригинала, затем выполняет атомарную замену. Ошибка копирования, фиксации оригинала или замены не публикует частичную миграцию. Coordinator считает загруженный старый профиль несохранённым и выполняет миграцию при обычном flush даже без пользовательской правки.
- Для больших legacy-альбомов writer выбирает компактный JSON, когда отступы превышают прежний лимит 32 MiB. Замер 64 максимальных страниц: `10 754 649` байт компактно и `56 857 887` с отступами. Лимит и все данные остаются прежними; тест проверяет также миграцию большого v7 и hash всех 64 рисунков по 2048 точек.

## Совместимость

`Entries` — источник истины v8. Поле `Album` сохранено как проверяемая проекция для существующего кода. Старые enum и DTO-поля не перенумерованы. Fixture без нового каталога сохраняет четыре исторические башни и восемь runtime-слотов с пустым хвостом. Исторический campaign validator явно использует четыре страницы, независимо от новой константы.

`WorkshopPersistence` сохраняет прежнее имя файла и правила кеширования пути. Проверка startup slots в контенте уже использовала общую константу, теперь равную восьми; отдельная перепись этих классов не понадобилась. Новые команды, смешанный запуск боя и экраны остаются задачами 5–12.

Полный PlayMode впервые после графического пилота обнаружил прежние расхождения: четыре теста ожидали сокет `0,34` вместо уже экспортированного `0,16`; проверка рельсы сравнивала число вершин разных графических маршрутов; preview неподходящего черновика с тремя пулемётами преждевременно включал пилот с двумя сокетами. Геометрия относительно базы `6cbeea5` не менялась. Проверки приведены к действующим authored-сокетам и фактическим UV рельсы; пилот применяется только к поддерживаемым сокетам. Это сохраняет возможность исправить невалидный черновик до публикации.

Старый HUD получил минимальную совместимость с восемью слотами: подписи и размеры карточек вычисляются по количеству. Полная переработка смешанного боевого интерфейса остаётся следующими задачами.
