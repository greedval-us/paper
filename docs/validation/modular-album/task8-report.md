# Задача 8 — генераторы и надёжные награды

База: `e86b2b5`. Unity `6000.5.7f1`.

## Реализация

- `GeneratorWaveLedger` принадлежит одной `GameSession` и фиксирует живые завершённые генераторы до старта волны. Выплата проверяет тот же экземпляр и ID среди выживших объектов, использует доход из начального снимка и выдаётся один раз. Построенный или завершённый во время волны генератор получает доход только со следующей полной волны. Продажа, уничтожение и подмена объекта не дают выплату. Ledger хранит текущую волну и монотонный номер, без накапливания истории всех выплат.
- Обычный генератор: 60 штрихов / 80 HP / 12 за волну; экономичный: 72 / 68 / 15. Окупаемость обоих — пять полных волн. Общий предел двух вариантов, только карандаш, возврат 0. Материал и усиления не умножают доход; генераторы не начисляют золото или XP.
- У партии есть новый `RunId`, а `CompletedWaves` учитывает только фактически завершённые волны. Чтение доступно через `IRunReadModel`. Генераторный доход подключён к общему зачислению штрихов на завершении волны.
- `WorkshopProfile.TryApplyRunReward` объединяет накопительный итог по GUID партии и начисляет только новую разницу: 8 золота / 10 XP за волну и один бонус 30 / 40 за победу. Восемь волн дают 94 / 120, пять — 40 / 50. Нулевая, повторная или меньшая запись ничего не меняет. Неизменяемый `RunRewardReceipt` читается независимо от будущих обновлений. Уже существующий DTO v8 сохраняет квитанции вместе с Gold/XP; повтор после загрузки не оплачивается.
- `RunRewardService` хранит ожидающие накопительные намерения, а не устаревшую копию профиля. Каждая попытка применяет их к последнему опубликованному профилю и сохраняет баланс с квитанциями одной транзакцией. Отказ IO не публикует часть награды. Покупка между отказом и повтором сохраняется; ожидающие результаты нескольких партий объединяются одной записью.
- `RunController` отправляет новые результаты один раз при изменении итогов, без повторных попыток на каждом кадре. `RetrySave` повторяет ожидающие награды; переход в мастерскую и новая партия сохраняют очередь. Явная смена профиля сначала должна сохранить ожидающее начисление. Отдельный признак ожидания поддерживает доступность повтора даже после успешной покупки.
- Новый настроенный маршрут альбома использует квитанции. Явные исторические стенды с короткими кампаниями и без нового каталога сохраняют прежний адаптер настраиваемого `GoldEarned`; существующие проверки выплат остаются обязательными.
