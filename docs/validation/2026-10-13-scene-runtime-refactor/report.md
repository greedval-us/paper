# Рефакторинг и исправление сцен — 2026-10-13

Unity 6000.5.7f1, Windows Editor, проект `paper`.

## Причина исходного сбоя

При включённых радиусах `NotebookWorldView.DrawStructures` запрашивал `WeaponRange` для каждой постройки без чертежа, включая стены и шипы. Адаптер `LegacyContentIds.Weapon` возвращает для них `tool.wall` и `tool.spikes` — корректные ID инструментов, которых нет в каталоге стволов. `GetWeapon` выбрасывал исключение при каждом повторном построении геометрии. PD1 в консоли был сериализованным сообщением этого исключения, а не повреждённым игровым ID.

## Изменения

- `TowerCatalog` вынесен из `TowerBlueprint.cs` в отдельный файл: неизменяемый чертёж отделён от расчёта характеристик и кэша сборок.
- Запрос радиуса для Wall/Spikes возвращает ноль без обращения к каталогу оружия. Неизвестные строковые ID по-прежнему отвергаются.
- Поиск слота оружия общий для адаптеров дальности и интервала действия. Исправлено применение улучшений дальности на втором и третьем креплениях. Для нескольких одинаковых стволов строковый API с явным индексом сохраняет независимость креплений.
- `DrawStructureRanges` отделён от построения геометрии укреплений; порядок радиусов и пять пакетных слоёв сохранены.
- `DrawingInput` читает фактическое состояние `NotebookWorldView.ShowRanges`, без второго bool. Tab корректно выключает радиусы, включённые кнопкой стенда, в обычном и строительном режимах.
- Исправлен инструмент переноса текста: многострочные throw/Debug.Log* определяются по границам выражения. Текст интерфейса после диагностики продолжает извлекаться. Существующие ресурсы и семантические сообщения не переписывались.
