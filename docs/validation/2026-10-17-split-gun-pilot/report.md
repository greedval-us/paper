# Этап 2, второй срез: составной пулемёт

17.10.2026 · Unity 6000.5.7f1 · рабочая ветка `codex/standard-workshop-stage1`. Продолжение [общих креплений](../2026-10-17-standard-mounts/report.md): раздельные группы движения для пулемёта на обычной основе, оба оружейных места. Полный пилот этапа 2 остаётся в работе.

## Что изменено

Подготовлены четыре прозрачных фрагмента: неподвижная опора, корпус люльки с приёмной трубой, пакет стволов и передняя муфта. Источники: [GunPilotParts-v1.png](../../../ArtSource/Notebook/NewStyle/GunPilotParts-v1.png), [точный промпт и происхождение](../../../ArtSource/Notebook/NewStyle/GunPilotParts-v1.provenance.json), [нарезка](../../../ArtSource/Notebook/NewStyle/sprites.source.json). Ориентиры — [A4](../../../ArtSource/Notebook/References/2026-10-17/sheets/A4-weapon-components.png) и прежний ModularSprites; новый лист является производным ассетом для проверки движения, а не объявлением всего A4 готовой библиотекой.

В [NotebookMounts.json](../../../Assets/PaperDefense/Resources/Art/NotebookMounts.json) добавлен необязательный пилот schema 2 для пары `chassis.standard` / `weapon.gun`. Сохранено чтение schema 1. Для каждого фрагмента явно размечены исходный холст, trim, attach, смещение, равномерный масштаб, угол, группа движения и слой. Эти числа не вычисляются из alpha bounds. Общий [NotebookMountLayout](../../../Assets/PaperDefense/Presentation/Art/NotebookMountLayout.cs) выдаёт позу, а [NotebookTowerComposition](../../../Assets/PaperDefense/Presentation/Rendering/NotebookTowerComposition.cs) использует её в сборках UI, preview, полигоне и мире.

| Узел | Движение | Слой |
|---|---|---|
| Опора | Неподвижна на своём сокете | 0 |
| Стволы | Поворот своего оружия и его отдача | 1 |
| Корпус люльки / приёмная труба | Поворот без отдачи; закрывает уходящий внутрь хвост стволов | 2 |
| Передняя муфта | Поворот без отдачи | 3 |

Ось поднята на шарнир над опорой: `pivotOffset=(0,46)` канонических пикселей. Тест до исправления показал перемещение основания люльки на 0,11337 U при повороте. Теперь точка шарнира остаётся неподвижной. Художественное дуло — пиксель `(444,460)` холста стволов 522×554; его положение и отдача проверены по UV реально выданного mesh. Валидация отвергает в том числе совпадение итогового дула с осью, которое обнуляло наведение.

Габарит preview резервирует весь поворот и отдачу вокруг шарнира, поэтому движение не меняет масштаб карточки. Другие основы и шесть остальных оружий используют прежние цельные иллюстрации; отдельные значки выбора оружия также пока остаются прежними. Исторические рисунки и явно заданная native theme сохраняют свои адаптеры. Core, баланс, рецепты, DTO и версия профиля v7 этим срезом не менялись.

Атлас расширен с 80 до 84 спрайтов. Для всех 80 прежних областей совпадают декодированные пиксели, размеры и логические bounds; исходные записи и aliases сохранены. [Результат сравнения](atlas-preservation.json), [повторяемый скрипт](compare-atlas-preservation.ps1), [независимое ревью](review.md). Лишнее изменение пробелов в theme asset после экспорта убрано, восстановлены исходные байты этого файла.

## Что ещё требуется для приёмки этапа 2

Основа пока остаётся цельным спрайтом, броня — прежним модулем. Следующий срез должен подготовить front/back основы и бронепластины, согласовать габариты двух соседних оружий и проверить крайние/промежуточные позы вместе с бронёй. Расстояние между нынешними стандартными сокетами около 0,2238 U меньше радиуса длинного ствола около 0,30 U; отсутствие пересечений при произвольном независимом наведении этим срезом не обеспечено. Порядок слоёв не решает эту геометрию, диапазон наведения в Core не сужен.

Поэтому весь этап 2 не объявлен завершённым и массовый перенос других семейств не начат.
