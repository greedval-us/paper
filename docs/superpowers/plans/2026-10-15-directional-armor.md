# Направленное усиление брони

Цель: следующий функциональный слой из принятого предложения — распределение защиты корпуса. Основа: Unity 6000.5, C#, существующие неизменяемые чертежи, DamageRules, uGUI и JSON-профили. Продолжаем в текущем дереве, сохраняя незакоммиченный этап веера.

## Контракт

- Отдельная ArmorDistribution: четыре сектора по 90° (перед, право, тыл, лево), 12 целых делений запаса. Сумма от 0 до 12; остаток явно показан. Одинаковое круговое распределение 3+3+3+3 сохраняет обычную защиту. Коэффициент стороны = деления/3; итог ограничивается существующим MaximumDefense. Лишняя концентрация не обходит предел, редактор показывает фактическую защиту.
- Запас не покупает новую броню: нужен установленный модуль слота Armor. Перераспределяется текущая FoundationDefense конструкции, здоровье, цена и нагрузка не меняются. При нулевой настроенной защите это явно видно. Старые страницы без схемы сохраняют обычную круговую защиту.
- Направление корпуса задаётся поворотами 90° в редакторе и хранится в странице. Нулевой перед смотрит вверх карты (+Y). Оружие вращается независимо. Граничные диагонали относятся к следующему сектору по часовой стрелке. Для совпадающего источника используется самый слабый сектор.
- При атаке учитывается положение врага, для летящего плевка — исходная точка траектории. Это применяется к ближним атакам, перехваченным плевкам и ответному огню полигона. Проба использует тот же DamageRules, один или четыре удара по 20, карандаш, без трат профиля.
- Редактор «Усиление» показывает авторский силуэт и штриховку секторов, запас/фактическую защиту, ориентацию и пробу. Кисть выдаёт одно деление на посещённый сектор за жест; повторное движение в секторе не расходует запас снова. ПКМ стирает, также есть кнопки +/−, шаблоны, отмена, поворот и возврат к обычной броне. Незавершённый жест отменяется при закрытии/потере фокуса/Escape/выходе за холст. Изменения попадают в черновик; сохранение обычным способом.
- Схема сохраняется при копировании, переименовании, изменении рисунка/оружия/основания; удаление последнего модуля Armor убирает её. Собственная версия схемы 1, неизвестная будущая версия блокирует перезапись профиля. Данные каталога также поддерживают слой и глубокое копирование.
- Усиленные стороны видны в миниатюрах и боевом отображении. Тексты через существующие ресурсы. Произвольные физические габариты корпуса не вводятся.

## Задачи

- [x] Модель и данные: ArmorDistribution, TowerBlueprint, BlueprintData, стартовые чертежи/копии каталога. Проверки бюджета, поворота, сохранения, удаления брони и будущих версий.
- [x] Бой и проба: DamageRules, три существующих места повреждения, ArmorProbe. Проверки источников, предела, фронта/тыла, круговой схемы и сохранения цены/здоровья.
- [x] UI и отображение: ArmorReinforcementPanel/Graphic, WorkshopHud, BlueprintSketch, DoodleGlyphs; ресурсные строки. Проверки указателя, отмены, доступа, ресурсы профиля.
- [x] Проверка в Unity: направленные тесты, реальный снимок с PlayerBalance.asset, полный EditMode/PlayMode/Python, независимое ревью, инструкция и отчёт.

Особое внимание: потеря слоя в копирующих конструкторах, неверная сторона перехваченного плевка, расход на каждом событии Drag, скрытый эффект сверх MaximumDefense, повреждение пользовательского профиля при проверках. Каждый пункт покрывается проверкой в соответствующей задаче.
