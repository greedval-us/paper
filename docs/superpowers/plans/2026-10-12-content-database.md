# Content Database Implementation Plan

**Goal:** Добавлять варианты деталей на существующих алгоритмах редактированием локального каталога, сохранив текущие пресеты, рисунки и профили.

**Architecture:** ScriptableObject — главный источник редактирования; Application строит проверенный снимок типизированного Core-каталога. Страницы ссылаются на устойчивые ID, атаки выбираются по закрытому типу алгоритма. Legacy enum/Flags остаются явным адаптером сохранений. Данные рисунка привязаны к устойчивым слотам.

**Tech Stack:** Unity 6000.5.7f1, C#, NUnit EditMode/PlayMode.

**Spec:** пользовательское задание «Каталог башен и баланс через данные», полученное 2026-10-12; исходная ветка `codex/full-album-loop`, commit `b759182`.

## Ограничения

- Не менять эффективный баланс, алгоритмы атак, GUID сцены/существующих asset, старые числовые ID и биты.
- Не читать/записывать реальный профиль в проверках; использовать memory-only и временные пути.
- Не выполнять push, публикацию, сброс или переключение ветки.
- Два рабочих крепления и четыре слота партии сохраняются. Новый алгоритм требует C#, его варианты — данных.
- Excel/JSON — экспорт и отчёт, не конкурирующий источник редактирования. В Player контент доставляется сборкой; hot reload вне объёма.

## Последовательность

- [x] Исходная полная регрессия; эффективные настройки двух пресетов, цены/характеристики сборок, детерминированные trial/replay.

- [x] ScriptableObject база и пресеты: мигрировать действующие записи без смены GUID/значений; Inspector + Editor validate/duplicate; разрешать все ссылки до публикации. Сравнить настройки/сборки до и после.
- [x] Сборка и бой по определениям: закрытые обработчики существующих атак, модули с конечными разрешёнными операциями, общая цветная квота, статистика по ID. Проверить порядок/округление и replay.
- [x] Данные рисунков, slot bindings и динамическая мастерская: контуры/pivots/версии оценки; прокрутка каталогов; все карточки/preview/trial читают одну конфигурацию. Тесты двух одинаковых оружий, смены одной детали и старого качества.

- [x] Зафиксировать хэш реализации; выполнить A–Д приёмки только новыми/изменёнными тестовыми asset, используя заранее подготовленный smoke harness. Сохранить diff и доказательство отсутствия правок runtime C# на этом этапе.

Доказательства и ограничения сравнения: [отчёт](../../validation/content/README.md).

## Проверка рисков

- Отсутствие override отличается от 0/false; редактор сообщает источник конечного значения.
- Неизвестный ID не подменяется Gun, не стирает страницу/линии и не позволяет перезапись неподдерживаемой схемы.
- Изменение asset не меняет начатый бой, оценку старого рисунка или его образец молча.
- Модули не создают крепления и не увеличивают вместимость рекурсивно; конфликты/повторы проверяются до оплаты.
- Прежние float-операции, приоритет целей, RNG, отложенные попадания и общий цветной бюджет сохраняются.

## Разделение файлов

- Core каталог, blueprint, формулы, combat/events/statistics: worker `content_combat_audit`.
- Profile/DTO, Application controller/read model, isolated persistence tests: worker `content_profile_audit`.
- Drawing model/templates/assessment/editor и Presentation: worker `content_ui_drawing_audit`.
- Authoring assets, presets/global tuning, Editor migration/validation, baseline/data-only harness, сборка/интеграция/отчёт: root.

DTO из `TowerBlueprint.cs` переносится отдельным файлом до параллельных правок. Общие API фиксируются работником Core и сообщаются остальным до интеграции.
