# Отдельная игровая сборка по концепту

Запрос: начать собирать игру из доступных механик, сохранив отдельные тестовые сцены. Визуальное направление: тетрадная бумага, синие чернила, рисованный замок, современные компактные панели, иконки вместо подписанных кнопок управления.

## Первый игровой срез

- Отдельная сцена `Scenes/Game/PaperDefenseGame.unity`; прежние сцены и prefab остаются стендами разработки.
- Главное меню → карта одной доступной миссии → подготовка четырёх чертежей → существующий восьмиволновый бой → результат.
- Существующая мастерская, редактор рисунка, альбом и полигон доступны из игровой оболочки.
- Новый HUD с иконками, ценами, выбранным состоянием и подсказками. Пауза и модальные окна блокируют строительный ввод.
- Ядро и экономика остаются общими. Продвижение новых механик начинается со стендов; этот срез не создаёт дополнительные карты или сохранение незаконченного боя.
- Профиль использует существующее защищённое хранилище; тесты и визуальная проверка запускаются в memory-only.
- Игровые Balance/Rules/Content выделены в самостоятельные assets; последующие сборки не переносят экспериментальные значения автоматически.

Реализация и итоги проверок: [руководство](../../Player-Game.md), [отчёт](../../validation/2026-10-14-player-game.md).

## Реализация и проверка

1. Проверить отдельный вход и состав сборки (RED).
2. Добавить композиционный корень и навигацию с явными состояниями, не копируя симуляцию.
3. Собрать экранные панели, векторные иконки и переиспользовать имеющееся оформление.
4. Подключить боевой HUD и переходы мастерской; сохранить значения по умолчанию старых сцен.
5. Создать сцену, переключить основной build entry, проверить переходы/паузу/изоляцию профиля автоматическими тестами.
6. Проверить реальную отрисовку, консоль и собрать отдельный Player для проверки пользователем.
