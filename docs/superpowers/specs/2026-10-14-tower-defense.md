# Notebook tower defense

Latest user direction supersedes the original fixed-road layout: an open terrain map, enemies approaching from all four sides, and freely placed barricades. Implement a complete playable main preset with larger distinct enemies, legible health, terrain and icon-led construction. Preserve the free drawing workbench and its economy: ink budget per design; gold unlocks; combat construction uses run ink.

## Rules

- Optional serialized battlefield definition in GameBalance, absent in legacy fixtures. A resolved immutable battlefield owns enemy walkability, tower placement, trap placement, barricade sites, entrances and decorative terrain placements. Core has no Unity dependency. All public snapshots are defensive.
- Main map remains 96 × 64 with a central castle and the existing three ink wells. Broad open clearings connect around groups of mountains and woods; terrain footprints block walking and construction. Towers, barricades and traps can be placed on any clear legal ground, with existing castle/well/border reservations. Preview and build use the same placement rule. No narrow scripted road mask in the main map.
- Main waves approach from west, east, north and south, with multiple spread-out perimeter entrances on each side. Enemies use deterministic weighted cardinal navigation around terrain and structures, bypassing or breaching player barricades. Congestion delays spawns without dropping them. Every configured entrance and enabled objective must connect; malformed definitions fail authoring validation. Fixed-road mode may remain an explicit optional configuration for compatibility, but is not the main game.
- Add two build choices: a slowing ground trap (TarPit) and a repair support post (RepairPost). They are configured like existing structures. Slow effects use strongest effect, never multiply to a permanent stop. Repair acts within radius at a finite rate, never revives dead structures, does not stack on the same target per simulation step, cannot repair other repair posts or itself. Existing spikes deal damage; barricades buy time; support protects an investment instead of dealing damage. Quotes, refunds, upgrades and completed/incomplete behavior remain atomic and consistent.
- Add two enemy families Brute and Bulwark alongside Doodle, Runner, Gnawer and Spitter. Brute is slow with high HP; Bulwark is a tough medium-speed escort. Existing drawing tiers continue to supply armor and visual markings. No arbitrary invulnerability or one-shot rule.
- Main-preset starting calibration: Doodle 60 HP, Runner 42, Gnawer 180, Spitter 110, Brute 420, Bulwark 260. Modern wave HP growth is configurable, linear +18% per completed wave; legacy fixtures default to zero modern growth. Display HP proportion for every enemy and distinct size by family (after visual acceptance: Doodle2.5, Runner2.3, Gnawer3, Spitter2.8, Brute4, Bulwark3.5). Numbers are subject to measured balance adjustment with recorded reasons.
- Main waves use fewer, stronger enemies (initial target 28, 38, 50, 64, 80, 100, 125, 155); introduce roles gradually and preserve configured wave rewards. Initial target barricade cost 14/HP 240, spikes 22, tar 30 with 35% slow, repair 80 with range 5 and 8 HP/sec. No reward/refund loop may create ink. Calibrate against actual starter blueprints, not nominal legacy gun stats.

## Presentation and assets

Keep the established vector notebook authoring pipeline and batched meshes. Extend canonical author_notebook.py/JSON/SVG resources reproducibly; do not introduce per-enemy objects. Six recognizable animated families, mountains, pine and broadleaf trees, rocks/shrubs, entrance markers and construction icons. Terrain and roads must visibly agree with placement and path rules. Terrain is static, cached geometry. UI uses large icons, short names, price/hotkey; one selected-tool explanation gives its purpose, restrictions and stats. Essential actions remain understandable without guessing icons. Adapt layout to 1280×720 and normal desktop sizes.
