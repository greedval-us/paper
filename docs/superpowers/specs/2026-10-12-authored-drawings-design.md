# Авторские страницы «ДЕРЖИ ЛИНИЮ» — предлагаемый дизайн

Статус: для согласования, не реализовано. Основание: мастер-промпт пользователя, §3–6,16–19; [аудит актуального кода](../../validation/master-prompt-audit-2026-10-12.md). Подтверждённый вариант мастерской не пересматривается: сборка и рисование до партии, на поле — копии четырёх выбранных страниц.

## Порядок этапов

1. Надёжное сохранение и единая конфигурация preview/оплаты/боя/полигона. Без изменения чисел и боевого баланса.
2. Минимальный путь авторских штрихов: редактор → альбом → перезапуск → набор → копии на поле, независимый поворот креплений.
3. Объяснимая оценка, один согласованный коэффициент темпа и сравнение одной конструкции при полном и пользовательском качестве.
4. Отдельное проектирование конечной экономики и перенос параметров в общий каталог, затем балансировка материалов/оборудования/эффектов.
5. По одной новой специализации оружия, с измеримыми слабостями и сравнением при одинаковом бюджете.

Каждый этап согласуется отдельно. 85–100%, динамическая подача, удаление урона из материала, броня в процентах защиты и лимит наложения цвета не являются принятыми правилами.

## Этап 1: сохранность и одинаковые правила

Application получает отдельный `WorkshopProfileStore` с экземпляром состояния записи; статический адаптер пути может остаться для совместимости. Предлагаемые контракты:

```csharp
enum ProfileLoadSource { NewProfile, Primary, Backup, RecoveryRequired }
ProfileLoadResult Load(string path); // Profile, Source, Message, CanWrite
ProfileSaveResult Save(WorkshopProfile profile); // Success, Message
bool RetrySave(out string reason);
ProfileSaveState // Saved, Unsaved, WriteFailed, RecoveryRequired, MemoryOnly
```

Сначала проверяется primary, затем backup. Новая игра допустима автоматически только при отсутствии обоих файлов. Неизвестная будущая версия не считается пустым/повреждённым профилем и блокирует автоперезапись, даже если рядом есть исправный backup старой версии: автоматический откат к нему недопустим. Если исправного источника нет, файлы сохраняются, интерфейс показывает проблему; можно работать с временным профилем в памяти, но без записи поверх исходных данных.

После восстановления из backup он остаётся исправным при первой последующей записи: нельзя отдать повреждённый primary в `File.Replace` как новый `.bak`. Новый снимок проверяется до commit. При нормальном сохранении используется существующая атомарная замена; при восстановлении старый backup сохраняется отдельно от заменяемого primary, а проблемный primary — в отдельной копии с уникальным именем. Исходные проблемные данные сохраняются до явного решения пользователя, автоматически ничего не удаляется. Защита проверяется также при повторной записи и выходе.

Ручные операции с альбомом, набором и открытиями выполняются транзакционно: кандидат → успешная запись → публикация памяти и события. `WorkshopProfile.CreateWorkingCopy()` копирует текущее валидное состояние без нормализации загрузчика и без начислений. Если запись не удалась, прежние золото/страницы/слоты остаются, а черновик редактора доступен для повторной попытки; состояние WriteFailed отличается от Unsaved для уже заработанной награды. В режиме тестов без persistence commit выполняется в памяти.

Заработанное золото требует другого правила: оно начисляется в память один раз независимо от IO, профиль помечается несохранённым. Повтор записи сохраняет полный снимок и не начисляет награду заново. UI показывает «изменения не сохранены» и действие повтора. Этот повтор сохраняет уже принятое в память состояние; отклонённая ручная покупка/сохранение черновика повторяется исходной командой, а не записью старого профиля с ложным подтверждением. Переход в мастерскую/новую партию не сбрасывает такой профиль. `OnApplicationQuit` не обходит защиту восстановления и не делает вид, что гарантирует запись при внезапном завершении процесса.

`TrialRunner` получает явный снимок актуального `GameBalance`; обе стороны сравнения используют его, не изменяя входные данные. Условия полосы остаются отдельными и явно указанными: готовые карандашные башни, фиксированные позиции, сценарные HP/скорость/число врагов, 60 секунд, упрощённый ответный огонь. Они не подменяются врагами кампании при исправлении конфигурации.

## Этап 2: данные рисунка и редактор

Рассмотрены три способа: PNG всей башни, свободная сетка физических деталей и векторные штрихи по закреплённым частям. Предлагаются **векторные штрихи по частям**: PNG не сохраняет редактирование и независимый поворот, свободный конструктор усложняет уже принятые ограничения. Состав остаётся в текущем TowerBlueprint; рядом добавляется отдельный неизменяемый снимок рисунка, без Unity Mesh/Texture в Core.

```csharp
DrawingPartKey // Base, Mount0, Mount1, Armor, Feed, Tracking, Decoration
StrokeSnapshot // PartKey, normalized Points, Width; defensive copies
DrawingSnapshot // FormatVersion, GeometryHash, Parts
DrawingOrigin // LegacyStandard / PlayerDrawing
DrawingAssessment // RuleVersion, DrawingHash, ConstructionHash, Quality, PartFeedback
```

Однотипные орудия различаются индексом крепления. Чертёж — сохранённая страница; разные рисунки одного состава имеют отдельные ID. Вложенные коллекции глубоко копируются при создании снимка; readonly-обёртки над изменяемым исходным массивом недостаточны. PNG/геометрия/миниатюры производные, исходные штрихи сохраняются.

Координаты нормализуются в заранее заданном пространстве листа/части, с фиксированными pivot и размещением. Нельзя автоматически подгонять bounding box авторских линий: это выпрямит/изменит пропорции. Zoom и pan влияют только на преобразование указателя. Каждая точка и толщина проверяются на конечность, допустимый диапазон и технические лимиты.

`DrawingEditorSession` отвечает за AddStroke/Erase/Undo/ReplacePart/SaveAsNew; `DrawingTemplateCatalog` — за бледный образец выбранного состава; отдельный компонент ввода — за захват указателя только внутри редактора. WorkshopHud связывает элементы, но не хранит алгоритм оценки или историю всех действий.

При замене Mount1 Gun→Mortar исполнение и оценка только Mount1 сбрасываются. Остальные части сохраняются. Undo возвращает заменённую часть, исходная страница альбома остаётся до явного сохранения; доступно сохранение новой версии. Украшения отображаются, но не добавляют оружие и не участвуют в оценке.

Новый совершенно пустой рисунок — только черновик. Старые страницы мигрируют как честно помеченные LegacyStandard с прежней эффективностью; этот режим нельзя выбрать для создания новых идеальных страниц. Все 64 старые записи, золото, открытия и набор сохраняются. Невалидные записи нельзя незаметно удалить при миграции.

Техническое предложение для проверки прототипом: до 128 штрихов и 2048 точек суммарно на страницу, до 64 страниц; координаты сериализуются в фиксированной сетке, общий предел профиля — 32 MiB UTF-8. Перед утверждением формата тест на максимальный валидный альбом должен доказать вместимость. Чтение и запись применяют один `ProfileLimits`; превышение отвергается до замены исправного файла. Миграция рисунков повышает версию формата и сохраняет исходную v1-копию.

## Рисунок на поле и независимый поворот

`DrawingGeometryCache` один раз готовит локальную геометрию по `(GeometryHash, BindingVersion)`. Основание и оборудование попадают в существующий статический batch, каждое оружие — в динамический с поворотом вокруг своего pivot. Миниатюра и поле используют ту же подготовленную геометрию. Авторские линии не проходят через добавляющий случайную кривизну процедурный renderer. Нет GameObject/Update на штрих или новый индивидуальный Mesh на каждую копию.

`WeaponMountState` содержит Aim/TargetId/AcquisitionRemaining/Cooldown для каждого из максимум двух креплений. Read model экспортирует соответствующие неизменяемые mount views; запись испытания сохраняет их. Захват проверяется в собственной дальности оружия. Направление соответствует фактической цели своего крепления. Фиксированная подача сохраняется; динамическое разделение не входит в этап.

Силуэт не задаёт физику: дальность, урон, количество орудий и клетка определяются составом. Третий декоративный ствол не стреляет. Длинный рисунок не получает дальность, узкий не уменьшает клетку. Цвет/материал/повреждения меняют оформление, но сохраняют длины и перекосы автора.

## Этап 3: оценка и испытания

Отдельный чистый `DrawingEvaluator` работает при изменении/загрузке рисунка, не в боевом кадре. Предлагается сравнение покрытия обязательных контуров и соответствия формы/расположения с допуском. Контуры и линии равномерно выбираются по длине; веса частей фиксированы правилами. Дубли не увеличивают покрытие; избыток линий вне контуров ухудшает соответствие. Украшения исключаются. Объяснение называет часть и незавершённый контур.

Проверяются дрожь, разная плотность точек, разрешение/zoom, повторное обведение и закрашивание. Неровный непустой рисунок остаётся пригодным. Художественный вкус, скорость, нажим и число движений не оцениваются. Удобство проверяется реальным рисованием мышью, а не только эталонными массивами.

Диапазон **85–100%** предлагается как первая гипотеза, требует отдельного согласования. При его принятии коэффициент `0.85 + 0.15 * quality/100` применяется ровно один раз к итоговому темпу после подачи/ограничений. Интервал делится на коэффициент; урон, HP, защита, дальность, цена, нагрузка, радиус и сила цвета не меняются. Preview, полигон и бой вызывают единый расчёт интервала.

В полигоне добавляется режим «тот же состав: полный темп против моего рисунка», с одинаковыми seed, бюджетом, размещением и актуальным балансом. Он дополняет существующее сравнение разных сборок. Учитываются конечный прогон и дискретный шаг симуляции, не обещается точное отношение числа выстрелов на любом коротком интервале.

## Критерии первого полноценного результата

Игрок собирает два пулемёта, рисует их по-разному, сохраняет новую страницу, перезапускает игру, узнаёт миниатюру, берёт страницу в набор и строит несколько копий. Линии каждой части одинаковы у копий и сохраняются при независимом повороте. Исходный профиль не потерян. Качество после согласованного этапа одинаково учитывается в preview/trial/бою, пустой новый черновик не становится идеальной башней.

Проверки этапов: IO-сбои и восстановление, полный альбом/миграция, deep-copy и замена одной части, реальные Canvas/world vertices, два направления, коэффициент один раз, остановка боя в редакторе/полигоне. Производительность измеряется отдельно после появления геометрии; старый сценарий 3000 врагов не доказывает FPS новых рисунков.
