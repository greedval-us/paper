# Границы механик и слоёв

Пользователь запросил рефакторинг кода для безопасного отказа от отдельных механик и дальнейшего развития игры. Уточнение: набор систем задаёт разработчик, игрок не выбирает механики. Текущий режим и сохранённые работы должны продолжить работать. Excel создаётся после рефакторинга из фактического runtime-баланса.

## Решение

Сохранить существующие сборки Core → Application → Presentation. В Core добавить сериализуемую `MechanicsConfiguration` и неизменяемое представление `MechanicsAvailability`. Application копирует конфигурацию из Inspector; партия и оружие фиксируют разрешённые возможности на старте. UI только читает возможности и не предлагает недоступные действия. Изменения во время партии не поддерживаются.

Все новые разрешения включены по умолчанию. Старые `EnableEnemyMechanics` и `EnableInkWells` сохраняются для совместимости. Первый ограничивает степени прорисовки, кляксы и плевунов; второй ограничивает чернильницы. Target-пресет не включает принудительно новые разрешения. Формат профиля, enum ID, художественные линии и открытия не меняются.

| Система | Владелец | Поведение при отключении |
|---|---|---|
| EnemyDrawingTiers | Спавн / правила эффектов | Sketch без дополнительного роста HP. Исторический рост сохраняется только при старом master=false |
| CorpseBlots | Контекст клякс | Нет пятен и бафа. Ручная очистка отказывает без оплаты; автоматическая не находит цели |
| RangedEnemies | Спавн / дальняя атака | Доля плевунов переходит обычным каракулям |
| InkWells | Необязательные цели | Нет точек, зарезервированных клеток, отвлечения врагов и добычи цвета |
| ColorCartridges | Цветные команды / payload оружия | Цветная команда отказывает атомарно, обычный урон сохраняется. Замедление скрепкострела работает |
| RunUpgrades | Развитие партии | Нет выбора и блокировки следующей волны |
| DrawingQuality | Каталог / оружие / полигон | Качество рисунка сохраняется как данные; коэффициент темпа равен 1 |

Общий таймер статусов не выключается вместе с отдельным источником эффектов. Очередь снарядов, движение, базовая экономика и переходы фаз остаются обязательным ядром. Динамическая подача уже имеет собственную настройку `Construction.DynamicFeed` и исторический fallback; второй переключатель не добавляется.

## Границы ответственности

`GameSession` координирует этапы шага, но не подменяет их флагом «все эффекты». Обработка статусов отделяется от жизненного цикла клякс и дальних снарядов. Развитие и общие выплаты отделяются от добычи чернильниц. Оружие использует узкий `IBlotContext`, не получает мастерскую, профиль или Unity. Общий баланс сохраняет прежний контракт владения; фиксируется отдельный снимок разрешений.

Core не обращается к Unity или IO. Application владеет запуском, командами и записью профиля. Presentation отображает read model и отправляет команды. Editor экспортирует данные для Excel, не становится runtime-зависимостью.

## Проверка

Исходный полный EditMode-прогон: 445/445, 0 ошибок. Новые проверки: каждое отключение, атомарность отказа, независимость статусов, наследование старых настроек, глубокая копия конфигурации, Target без повторного включения систем, нейтральное качество в полигоне, все 128 сочетаний семи разрешений в короткой партии до победы. После изменений выполнить полный EditMode и PlayMode и проверить консоль.

## Excel

Unity Editor загружает NotebookBalance и TargetNotebookBalance и вызывает `CreateWorkshopBalance()`. JSON содержит итоговые определения, правила, разрешения и эталонные производные. Генератор создаёт `.xlsx` с русскими листами механик, числовых параметров, деталей, оружия, материалов/врагов, волн и расчётов. Формулы имеют явные единицы и условия; значения Target извлекаются после применения пресета. Файл — справочник и расчётный инструмент, изменения ячеек автоматически не импортируются в игру.
