# Отдельные сцены механик

Откройте `Paper Defense → Validation → Open mechanics hub` и нажмите Play. [Общий экран](Mechanics-Hub.md) содержит карточки всех 26 стендов, фильтры по механикам и переходы с полной выгрузкой предыдущей сцены. Кнопка «К стендам» возвращает в меню.

Каждую сцену можно также открыть напрямую из `Assets/PaperDefense/Scenes/Tests` в режиме **Single**. Сцены не включаются в обычный Build Settings. Для проверки используйте одну сцену за раз: общие `Camera.main` и `EventSystem.current` принадлежат активному стенду.

`Paper Defense → Validation → Generate missing mechanics scenes` вызывает `PaperDefense.Editor.MechanicsTestSceneTools.GenerateMissing()`. Команда создаёт только отсутствующие сцены и данные, сохраняет открытую сцену активной и не сохраняет её несохранённые правки. Существующие тестовые сцены и assets не перезаписываются; production-сцена, prefab, GUID и Build Settings не меняются.

Сохранённая сцена содержит один `MechanicsTestScene` и ссылку на свой `Scenario.asset`. Единственная мировая камера создаётся при Play внутри заранее подготовленного неактивного корня bootstrap. Поэтому в редакторской сцене нет второй камеры, которая могла бы пережить подготовку и начать отрисовку параллельно. WorldView использует существующую плоскую отрисовку и не требует Directional Light.

## Управление и данные

Каждый `Assets/PaperDefense/Configuration/Tests/<id>/Scenario.asset` хранит seed, конечный запас штрихов/цвета, режим, точные флаги механик, размещения, мишени с известными HP и кляксы. Рядом находятся собственные `Catalog.asset` и `Preset.asset`. Каталог — глубокая копия действующего Target с его overrides, всеми нужными открытиями и четырьмя допустимыми стартовыми страницами. Production-каталог не используется для записи, а отключение ненужных механик не повреждает StartingPages.

В левой колонке боевых стендов показаны инструкция, наблюдения, счётчики HP, захват цели и нормализованная работа каждого крепления, длительности эффектов, запас цвета, точки и экономика по необходимости. Сборка, рисунок и профиль создают собственные интерфейсы: лишние панели и скрытые редакторы в этих сценах не создаются. Полная мастерская и полный боевой HUD доступны в Integration. Тексты берутся из назначенного `TextResourcesAsset`, включая подписи стенда.

- **Сброс** заново создаёт memory-профиль, session, контроллер, renderer, наблюдения и часы с тем же seed. Награды прошлого запуска не сохраняются.
- **Пауза / продолжить** в боевых стендах очищает долг часов. **Шаг** выполняет ровно один fixed tick 1/30 с, даже в паузе. В отдельных интерфейсах сборки, рисунка и профиля этих кнопок нет.
- **Вариант** пересоздаёт стенд. Цвет: красный, синий, зелёный. Подача: 1, 2, 3 пулемёта, затем два пулемёта и мортира без подходящей цели.
- Строительство, обновление материала, стирание, активация точки и выбор усиления используют обычные команды `RunController`.

Обычные стенды выбирают MemoryOnly до первого `Awake` bootstrap и выполняют ноль операций profile IO. Фабрика `GameSession.CreatePrepared` принимает только ограниченные неизменяемые исходные данные, проверяет числа, определения, границы/заполняемость клеток и включённые зависимости. После подготовки цели получают обычные атаки, эффекты, награды и смерть. Неподвижная мишень имеет нулевую скорость; если она находится в радиусе удара по центру, обычная атака остаётся возможной.

Автоматический `Update` контроллера отключён во всех стендах. Время продвигает только `MechanicsTestScene`; обычный шаг проходит через `RunController.StepSimulation`. Pressure использует единственный существующий `PressureScenario.Step` и отображает ту же session через контроллер, поэтому две симуляции не запускаются.

## Временный профиль

Только `12_ProfilePersistence` получает `FixtureStore`. Путь всегда создаётся программой под `Path.GetTempPath()/PaperDefenseMechanics/<новый GUID>/fixture.json`; выбрать production-путь через Inspector нельзя. Каждый вызов IO проверяет принадлежность этому каталогу.

1. Сохраните копию дважды, чтобы появилась предыдущая успешная версия в `.bak`.
2. Включите отказ записи, сохраните ещё одну копию: действие отвергается, прежний альбом остаётся. Выключите отказ и повторите сохранение.
3. **Перечитать** заново открывает те же временные файлы. **Прочитать backup** намеренно повреждает только временный primary и перечитывает store.
4. **Подготовить v5** создаёт отдельный валидный профиль v5; следующая успешная запись использует текущий механизм `.v5-original`.
5. **Новый fixture** и обычный **Сброс** создают новый каталог и свежий профиль. Выход из сцены удаляет только принадлежащие fixture файлы без рекурсивного удаления.

## Автоматическая и ручная проверка

`MechanicsSceneInventoryTests` проверяет 23 сохранённых файла механик и три художественных стенда (26 сцен всего). `SessionPreparationTests` проверяет владение данными, неподвижность, повторяемость и отклонение недопустимых исходных условий. `MechanicsSavedSceneTests` действительно открывает каждый сохранённый файл в PlayMode, проверяет единственный контроллер, 1–2 камеры, один EventSystem, подготовку, изоляцию, шаг/паузу, целевое поведение и свежий сброс. В Pressure проверяется фактический пик 3000 врагов; в Profile — чтение, запись и атомарный отказ. Тесты не открывают production-сцену после завершения.

Сводные результаты запуска и оставшиеся ограничения фиксируются в свежем отчёте проверки всего изменения. Визуально отдельно проверьте читаемость трёх креплений/колец на обычном масштабе, отсутствие лишних панелей, полёт сгустков, эффекты цвета и профильный статус. Для фактического времени кадров Pressure включите Unity Profiler на своём устройстве; счётчик навигации не заменяет профиль CPU/GPU.

Три отдельных стенда ассетов, анимаций и эффектов описаны в [руководстве оформления](Notebook-Art.md).
