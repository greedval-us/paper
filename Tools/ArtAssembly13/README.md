# Production modular art integration

`build-catalog.mjs` integrates the unchanged transparent PNG sheets produced for task 13. It reads the 54 production definitions from `PlayerAssemblyCatalog.asset`; it does not change any balance value or profile data. From the repository root, run `node Tools/ArtAssembly13/build-catalog.mjs`, then `node Tools/ArtAssembly13/pack-catalog.mjs 0`, and finally `Paper Defense → Art → Rebuild blue pen atlas` in Unity. Commit the generated source JSON and `Tools/ArtAssembly13/packing-4096.json` together. The Editor rebuild never invokes Node.

The source sheets follow the object references in `docs/design/album-assembly-2026-10-17/art/01-towers.png`, `02-weapon-parts.png` and `03-structures.png`. Full concept pages are never imported as modular sprites. The historical gun pilot remains unchanged in the legacy blueprint adapter. Modern recipes use `StandardFoundation-v9.png`, its inspected two disk centres (368,640) and (1163,640) on the bottom-left pixel canvas, a low isometric plinth and a compact fixed hub. One uniform scale (0.0006276353885315664) and position (-0.4822571556263724,-0.43584730777451763) retain both prior logical socket positions. The native crop is x17/y290/1503×444; contiguous base/front/roof bands occupy y290–384 / 384–511 / 511–734. The conservative front keepout covers the actual outer vertical corner faces. Minimum swept-envelope clearance is +0.004294 U; smallest moving-weapon/base height ratio is 0.734645 against the unchanged 0.65 threshold. Receivers use real opaque lowest-foot landmarks to seat on the front inner lip; the receiver-mounted sight remains attached when the head recoils. The moving weapon envelopes stay near 0.22 U. New family silhouettes have their own mechanism and head bindings; foundation variants, feed, turn, sights, cartridges and triggers have separate bindings. `armor.none` and `utility.none` deliberately have no sprite. Measured coordinates, exact prompts and rejected v7/v8 iterations are recorded in `StandardFoundation-v9.provenance.json`; requested prompt coordinates are not substituted for measured landmarks.

The PNG decoder in this tool only inspects alpha to select padded import rectangles. It never writes or alters PNG pixels. Mechanical attachment and muzzle points are authored separately on the full cell canvases. The manually recorded transparent gutters handle the source sheets' uneven cell spacing. The original repair parts had overlapping rectangular bounds, so their replacement is a separate production sheet rather than an alpha mask made from the concept.

`inspect-alpha.mjs <PNG> [...]` reports connected alpha bounds without changing the source files. This supports review of crop gutters; connected components do not determine mechanical anchors.

The generated `full-catalog-layout.json` records the exact import crops. `assembly-parts.source.json` remains the editable source for full canvases, trims, fixed/rotating/recoiling layers, foundation sockets, muzzle points and physical occupied regions. Atlas repacking changes UV placement only. The Unity importer rejects downsampling of any source crop and preserves the existing resource GUIDs.

Source fit parts use canonical semantic socket labels and schema 1. Import validates their identity, revision, category and socket metadata before derivation, and checks visual definitions against the production component catalog. An unknown collision mode or a mismatched source definition is rejected before packing or publication; supplied part metadata is never silently rebuilt to conceal disagreement.

`node Tools/ArtAssembly13/audit-catalog.mjs --source-fit` independently checks the authored frame mounts, transformed solid bands, fixed stands, swept weapon circles and neighbouring mounts before Unity import. Use `--runtime` after import to audit the exported data as well. The 28 standard frame/family combinations contain 56 occupied mounts.

Add `--variants` to test all 14 foundation choices against every actual frame, mechanism and nonempty socket subset. It reports a real physical-fit witness for each choice rather than assuming the standard frame accepts every hull. All three hulls retain the frame's own roof and foreground bands, owned by the selected hull ID in both rendering and Core data. Facade feeds use the same real central mounting point across frames and draw above the foreground wall. `AssemblyFoundationVariantArtTests` also checks actual alpha contacts and the selected optics/controller's surviving native pixels after the complete draw order.

`node Tools/ArtAssembly13/pack-catalog.mjs 0` searches deterministic non-rotating MaxRects heuristics and writes `packing-4096.json` only when all native crops plus the 9×9 pen tile fit with genuine 4-pixel gutters. Catalog `modular-full-catalog-2026-10-22-v7` retains a 4096×4352 atlas (68 MiB RGBA), 4 MiB more than the former square. Fallback relocation can use immutable accepted `packing-baseline-v5.json` or `packing-baseline-v3.json`; it verifies every unchanged seed rectangle's dimensions and all bounds and padded overlaps before writing. The Editor reads only the resulting declarative layout, strictly validates IDs, order, native dimensions, bounds, count and every four-pixel separation, and rejects stale layouts before publication with the regeneration command. It copies original RGBA rows into the atlas PNG without resampling or rotating pixels. `NotebookNativeAtlasTests` verifies every PNG pixel of all 140 crops and the imported resource dimensions. Unity's existing alpha-transparent RGB dilation remains an importer operation; the byte-for-byte source guarantee applies to the generated PNG. Whole-atlas mipmaps stay disabled because they would mix adjacent crops at low LODs.

The battery uses the top-left 627-pixel cell of `BatteryFoundation-v3.png`, an independently authored compact source with three real disks. Its 564×192 native import crop replaces the old tall block. The larger `BatteryFoundation-v2.png` was rejected for packing density and is not imported. `contact-audit.mjs --probes` reads current alpha and reports receiver-foot and sight-contact positions without changing any image or source metadata.

`AssemblyVisualComposer.Compose`, `ComposePart`, and the world/trial adapters use the same source transforms. Core certifies the conservative union of all compatible component variants for each mechanism, including recoil endpoints, neighboring mounts, fixed supports, selected body/armor keepouts and all four frame layouts. Static support families require explicit site/function/shell/utility coverage and occupied regions. Unknown revisions and unsupported combinations fail before save.

For the final screen comparison, run `node Tools/ArtAssembly13/build-fidelity-gallery.mjs --require-complete --require-reviewed`. The first flag checks PNG/sidecar integrity for the 30×5 source/before/after matrix; the second requires matching explicit manual reviews from the three `scene-fidelity-*-review-2026-10-22.json` reports. A changed source/capture hash or art revision invalidates the old visual proof. Image existence never supplies an art verdict. The generated gallery shows each reviewer, report link and remaining differences; current acceptance and full Unity results are in `docs/validation/modular-album/scene-fidelity-report.md`.
